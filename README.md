# 라이브 스트리밍 자극물

AI 시청자 연구용 실험 자극물. 정적 파일 하나로 동작하므로 GitHub Pages에 그대로 올라갑니다.
행동 로그는 Supabase로 들어갑니다.

---

## 1. 배포

1. 새 레포를 만들고 이 폴더의 파일을 전부 올립니다.
2. Settings → Pages → Source를 `Deploy from a branch`, 브랜치 `main` / 폴더 `/ (root)`로 지정.
3. 1~2분 뒤 `https://<계정>.github.io/<레포>/` 로 열립니다.

로컬 확인은 폴더에서 `python3 -m http.server 8000` 후 `localhost:8000`.

---

## 2. 로그 서버 (Supabase)

`index.html` 상단의 두 줄만 채우면 됩니다.

```js
const SUPABASE_URL = 'https://xxxxxxxx.supabase.co';
const SUPABASE_KEY = 'eyJhbGciOi...';   // anon public key
```

### 2-1. 준비

[supabase.com](https://supabase.com)에서 무료 계정을 만들고 프로젝트를 하나 생성합니다.
Project Settings → API에서 **Project URL**과 **anon public** 키를 복사합니다.

anon 키는 공개되는 값입니다. 자극물이 브라우저에서 돌아가므로 참가자가 소스를 보면 보입니다.
아래 RLS 설정이 그 전제에서 안전을 담보합니다 — 쓰기만 되고 읽기는 막힙니다.

### 2-2. 테이블 생성

Supabase 대시보드 → SQL Editor에 그대로 붙여넣고 실행합니다.

```sql
-- 세션 1건 = 참가자 1명의 자극물 1회 실행
create table sessions (
  id          uuid primary key,
  pid         text,
  condition   jsonb,
  started_at  timestamptz default now(),
  user_agent  text,
  screen_w    int,  screen_h    int,
  viewport_w  int,  viewport_h  int,
  tz          text
);

-- 이벤트 1건 = 행동 1개
create table events (
  id          bigserial primary key,
  session_id  uuid references sessions(id),
  t           numeric,      -- 세션 시작 기준 경과 초
  type        text,
  data        jsonb,
  created_at  timestamptz default now()
);

create index on events (session_id);
create index on events (type);

-- 참가자는 쓰기만 가능하고 읽기는 불가
alter table sessions enable row level security;
alter table events   enable row level security;

create policy "anon insert sessions" on sessions
  for insert to anon with check (true);
create policy "anon insert events" on events
  for insert to anon with check (true);
```

`select` 정책을 만들지 않았으므로 anon 키로는 조회가 안 됩니다.
분석은 대시보드에 로그인해서 하거나 service_role 키로 합니다. **service_role 키는 자극물에 넣으면 안 됩니다.**

### 2-3. 확인

자극물을 한 번 돌리고 `방송 나가기`를 누른 뒤, 종료 화면에
`서버로 전송했습니다. session_id: ...` 가 뜨면 연결된 것입니다.
Supabase → Table Editor → events 에서 행을 확인합니다.

### 2-4. 전송 방식

- 이벤트를 모아 **5초마다** 한 번에 보냅니다. 건당 요청을 보내면 300명 × 수천 건이 전부 개별 요청이 됩니다.
- 탭을 가리거나 창을 닫을 때 `keepalive`로 남은 것을 밀어 넣습니다.
- 전송이 실패하면 브라우저에 쌓아두고 다음 기회에 다시 보냅니다. 중간에 와이파이가 끊겨도 유실되지 않습니다.
- `SUPABASE_URL`이 비어 있으면 전송을 건너뛰고 로컬에만 쌓입니다. 종료 화면의 `JSON 내려받기`로 받을 수 있습니다.

### 2-5. 내보내기

```sql
-- 세션별 요약
select s.pid, s.condition->>'study' as study, s.condition->>'cong' as cong,
       s.condition->>'label' as label, (s.condition->>'viewers')::int as viewers,
       e.data->>'dwell_sec' as dwell, e.data->>'subscribed' as subscribed
from sessions s
join events e on e.session_id = s.id and e.type = 'leave';

-- 이벤트 전체 (SQL Editor 결과창에서 CSV 다운로드)
select s.pid, e.t, e.type, e.data from events e join sessions s on s.id = e.session_id
order by s.pid, e.t;
```

### 2-6. 용량

이벤트 1건이 대략 0.3KB입니다. 참가자 1명이 수백~2천 건이면 한 명당 0.1~0.6MB,
330명이면 **최대 200MB 수준**입니다. 무료 티어(500MB)에 들어갑니다.
밀도가 높은 조건(9,238명)을 많이 돌릴 계획이면 `comment_shown` 이벤트에서
`text` 필드를 빼는 것만으로 절반 이하로 떨어집니다.

## 3. 조건 지정

Study 2 전용입니다. 참가자는 링크를 타고 **바로 방송으로 들어갑니다** — 방 목록이나 선택 단계가 없습니다.
조건은 **코드**로 넘깁니다. 주소에 `cong=half`처럼 쓰면 참가자가 보고 조작을 알아챕니다.

```
https://skku-livestreaming.github.io/watch/?c=m2
```

참가자 ID는 **안내 페이지에서 직접 받습니다**. 링크에 넣지 않습니다.
고유 코드나 이메일 주소 둘 다 받습니다 — `@`가 들어 있으면 이메일 형식을 검사하고, 아니면 코드로 봅니다.

| 코드 | 의견 일치도 | 채팅 정체성 |
|---|---|---|
| `q7` | 전부 일치 | AI |
| `m2` | 절반 | AI |
| `z5` | 전부 불일치 | AI |
| `b9` | 전부 일치 | 사람 |
| `k3` | 절반 | 사람 |
| `r6` | 전부 불일치 | 사람 |

입력값은 공백 제거·소문자 변환 후 세션 행의 `pid`에 들어갑니다. 설문 응답과 묶는 열쇠입니다.
**이메일을 받는 경우 개인식별정보이므로 IRB 동의서에 수집 사실과 보관 기간을 넣어야 합니다.**
고유 코드만 받으면 그 부담이 없습니다.

점검할 때는 개별 파라미터로 덮어쓸 수 있습니다. **참가자 링크에는 쓰지 마세요.**

| 파라미터 | 값 | 설명 |
|---|---|---|
| `cong` | `all` \| `half` \| `none` | 의견 일치도. 참가자 투표 기준 |
| `label` | `human` \| `mixed` | 전원 사람 또는 AI |
| `ratio` | 0–100 | AI 비율. `label=mixed`일 때만 |
| `viewers` | 정수 | 표시 시청자 수 (기본 1,243) |
| `pollwin` | 0–90 | 투표 제한 시간(초). **기본 0 = 무제한(파일럿)**. 본실험은 파일럿 분포로 값을 정해 넣습니다 |
| `why` | `on` \| `off` | 다른 사람 이유 노출 |
| `intro` | `on` \| `off` | 안내 페이지 |
| `input` | `on` \| `off` | 참가자 채팅 입력 허용 |
| `seed` | 정수 | 닉네임·배정 seed |
| `theme` | `light` \| `dark` | 전 조건 동일하게 고정해 쓸 것 |

### 흐름과 시각

| 시각 | 일어나는 일 |
|---|---|
| 안내 | 조건 정보 확인 + 이메일 입력 |
| 0초 | **진행 중인 방송에 중도 입장**. 채팅창에 이미 지나간 대화가 쌓여 있고 입력도 열려 있음 |
| 22초 (`ANNOUNCE_AT`) | **영상에서** 스트리머가 "투표 올릴게, 그동안 채팅 닫을게"라고 말하는 시점. 채팅에는 아무것도 띄우지 않음 |
| 22~30초 | 그 말에 반응하는 채팅이 올라옴. 로그에 `phase: 'pre_poll'` |
| 30초 (`POLL_AT`) | 스트리머가 질문을 던지고 투표 카드. **이때 채팅이 잠김** |
| 투표 | 제한 없음(기본). 고르면 바로 그 자리에 이유 입력란. **보내기 전까지 선택을 바꿀 수 있음** |
| 보내기 | 투표와 이유가 **동시에 확정**. 이후 변경 불가 |
| 확정 + 3초 | 채팅 다시 열림. 이후 발화에 논거를 담은 찬반 의견이 붙음 |
| 200초 (`OUTRO_AT`) | 스트리머가 방송을 접으려 함. 채팅이 인사로 바뀜 (`phase: 'outro'`) |
| 230초 (`END_AT`) | 화면이 꺼지고 **추천 화면** — 구독하기 + 다른 영상 3개. 채팅은 남고 입력만 막힘 |
| 240초 (`SPAN`) | 영상 길이. 참가자는 아무 때나 '방송 나가기' |

종료 화면의 구독과 다음 영상 클릭이 마지막 행동 지표입니다. **"갈 때 붙잡는가"** 를 봅니다.
구독 로그의 `where`가 `header`인지 `endcard`인지로, 보는 중에 누른 것과 떠날 때 누른 것을 구분합니다.
추천 영상은 클릭해도 이동하지 않습니다 — 자극물 밖으로 나가면 이후 행동을 못 봅니다.

입장 전 대화는 로그에 `before_join: true`로 표시됩니다. 입장(stance)이 없으므로 일치도 분석에서 빠집니다.
투표 전 구간의 채팅 행동은 개인차 기저선으로 쓸 수 있습니다 — 해제 전후를 나눠 보십시오.

이유는 **사실상 필수**입니다. 비우고 보내기를 누르면 받지 않습니다. 채팅 작성은 **선택**입니다.

투표는 보내기 전까지 몇 번이고 바꿀 수 있고, 바꾼 이력이 `vote_click`에 전부 남습니다.
한 번에 고른 사람과 왔다갔다한 사람은 다른 참가자입니다 — `n_clicks`와 `settle_sec`으로 구분합니다.
다만 **반응 시간을 '숙고'로 읽지 마십시오** (Evans et al. 2015). 갈등 지표로만 사전등록합니다.

**파일럿은 투표 제한을 두지 않습니다.** 사람마다 얼마나 걸리는지를 보는 것이 목적이고,
그 분포로 본실험의 제한 시간을 정합니다. 무제한에서는 해제 시각이
**이유를 제출한 시점 + 3초**이므로 참가자마다 다릅니다. 로그의
`chat_unlocked`와 `chat_exposure_sec`로 정확히 남으니 분석에서 공변량으로 넣습니다.

`pollwin`에 값을 주면(예: 60) 해제가 **전 참가자 공통 고정 시각**(20 + pollwin + 3초)이 되어
노출 시간이 같아집니다. 본실험에서 쓸 방식입니다. 이 모드에서는 해제 시각이 지나면
이유가 적힌 만큼 자동 제출됩니다.

### 노출 기준 2종 — 섞어 쓰지 말 것

`comment_shown`은 **피드에 붙었다**는 사실이지 본 것이 아닙니다. 스크롤이 위에 가 있으면 화면 밖에 쌓이고,
밀도가 높으면 읽기 전에 밀려 올라가고, 탭을 가린 동안에도 쌓입니다.
그래서 종료 요약에 두 기준을 나란히 둡니다.

| 기준 | 필드 | 뜻 |
|---|---|---|
| 렌더 | `shown_congruent` / `shown_incongruent` / `shown_congruence_ratio` | 피드에 붙은 개수 |
| 화면 체류 | `seen_congruent` / `seen_incongruent` / `seen_congruence_ratio` | 채팅창 안에 1초 이상 떠 있던 개수 |
| | `visible_ms_congruent` / `visible_ms_incongruent` | 입장별 누적 화면 체류 시간(ms) |
| | `lines_total` / `lines_seen` / `lines_offscreen` | 피드에 들어온 전체 줄 / 1초 이상 본 줄 / 한 번도 안 뜬 줄 |

**두 기준의 차이 자체가 보고할 값입니다.** 실측 예시 — 같은 조건에서

| 시청 방식 | 미노출 | 일치율 (렌더 → 체류) |
|---|---|---|
| 그냥 보기 | 0건 | 43.3% → 43.3% |
| 위로 올려놓고 방치 | 31건 | 43.3% → **66.7%** |
| 탭 가림 | 31건 | 43.3% → **66.7%** |

조건 효과는 설정값으로 묶되, 처치강도에는 체류 기준을 쓰십시오.

`shown_*`과 `lines_*`은 **세는 대상이 다릅니다.** `shown_*`은 타임라인 발화만,
`lines_*`은 백로그·예고 반응·참가자 본인 글까지 포함한 모든 줄입니다. 두 수를 직접 빼지 마십시오.

한계 — **화면에 있었다 ≠ 읽었다.** 시선 추적 없이는 그 이상 불가. 논문에는 "읽은 메시지"가 아니라
"화면 노출 시간"으로 기술하십시오.

분석에 쓸 때 주의할 점은 `claude/behavior-measures-flow.md`와
`claude/behavioral-measures-refs.md`에 정리돼 있습니다.
특히 **카드를 연 것을 '정보를 찾아본 행동'으로 읽지 말 것** — 호버는 비용이 0이라 그 해석이 성립하지 않습니다(Kang et al. 2009). 클릭은 비용이 있어 로그에서 구분해 둡니다.

## 5. 수정할 곳

- **채팅 스크립트** — `const SCRIPT = [...]`. 투표 전까지 흐르는 주변 잡담이며 **순서대로** 재생됩니다.
  분류별로 묶어두면 인사말이 한꺼번에 몰려나와 목록처럼 보이므로, 한 편의 대화처럼 섞어 씁니다.
  **시점은 4시간 방송의 3시간 30분쯤**입니다. 오래 있던 사람들의 채팅이라 인사나 "소리 괜찮나요" 같은
  입장 직후 말투는 넣지 않습니다. 경과 시간 언급, 앞서 나온 얘기 되새김, 방종 임박, 스트리머 체력 걱정,
  짧은 리액션이 주를 이룹니다. 참가자 본인이 방금 들어온 사람이므로 "방금 들어왔는데" 류는 한둘만 둡니다.
  지금은 영상이 플레이스홀더라 주제에 의존하지 않는 줄만 들어 있습니다.
  **딜레마를 암시하는 줄은 넣지 마십시오.** 투표 전에 주제가 새면 사전 의견이 오염됩니다.
  같은 이유로 `DILEMMA.neutral`은 `POLL_AT` 이후 자리에만 들어갑니다.

  **입장 전 백로그는 같은 타임라인의 앞부분입니다.** 따로 뽑으면 백로그에서 쓴 줄이
  입장 직후 다시 나와 반복 구간이 생깁니다. 한 대본을 이어서 쓰므로 백로그와 그 이후가
  한 편의 대화가 되고, 문장은 세션 안에서 한 번씩만 나옵니다.
  짧은 리액션(`REACTIONS`)은 반복돼도 자연스럽지만 직전 4개 안에 쓴 것은 다시 뽑지 않습니다.
- **영상** — 현재 SVG 플레이스홀더입니다. `.player` 안의 `.scene`을 `<video>`로 교체.
- **딜레마** — `DILEMMA`(고릴라). 찬반 이유 풀이 각 24개입니다. 사전검사 응답으로 교체하는 것을 권합니다.

  선택지에는 **부연 설명을 달지 않습니다.** "수가 너무 많다" 같은 한 줄이 붙으면 그 자체가 한쪽 논거가 되어
  투표를 유도합니다. 같은 이유로 이유 입력란에도 **placeholder 예시를 두지 않습니다.**
  조건(맨손, 무기 없음, 100명 대 1마리)은 본문에서만 설명합니다.
- **마무리 발화** — `REACT_OUTRO`. 스트리머가 접으려 할 때의 인사입니다.
- **추천 영상** — `END_VIDEOS`.
- **예고 반응 발화** — `REACT_SIGNAL` / `REACT_NOISE` / `REACT_LOCK` 세 갈래. 입장이 없는 메타 발화라 일치도 조작과 무관합니다.

  실제 플랫폼은 투표 예고를 채팅에 쓰지 않습니다 — 스트리머가 말로 합니다.
  그래서 플랫폼 공지 줄을 띄우지 않고, **이 반응들이 참가자가 받는 유일한 신호**입니다.
  전부 "ㅇㅋ"면 무슨 일인지 알 수 없고 전부 설명조면 대본처럼 읽혀서, 세 갈래를 비율로 섞습니다.

  | 갈래 | 개수 | 위치 | 예 |
  |---|---|---|---|
  | `REACT_SIGNAL` | 2~3 | 앞쪽 40% | 오 투표? / 채팅 닫는대? / 뭐 물어보려고? |
  | `REACT_NOISE` | 나머지 | 전 구간 | ㅇㅇ / ㄱㄷ / 오오 투표 ㄱㄱ / 기대 |
  | `REACT_LOCK` | 1~2 | 뒤쪽 50% | 아직 쓸 말 남았는데 / ㅈㅅ 한 마디만 |

  `REACT_LOCK`은 채팅이 닫히는 걸 아쉬워하는 반응입니다. 현실감은 올라가지만
  "닫히는 게 아쉬운 일"이라는 프레임을 미리 깔 수 있어 1~2개로 제한했습니다.
- **닉네임** — 실제 이용자의 핸들을 쓰지 않습니다. 실존 계정에 하지 않은 말을 붙이게 되고,
  온라인 핸들은 개인정보라 IRB에서 걸립니다. 대신 한국어 스트리밍 채팅 닉네임의
  **표면 특성 분포**에 맞춰 생성합니다.

  조정 지점은 `NICK_MIX`입니다. 치지직·SOOP 방송 몇 개를 훑어 유형별 비율을 세고 이 숫자만 바꾸면 됩니다.

  | 유형 | 기본 비율 | 예 |
  |---|---|---|
  | 한글 단어·구 | 38% | 침대와한몸, 창가자리, 늦잠29 |
  | 영타 한글 | 20% | rlfls99, skanfu42, wjdalsrn00 |
  | 영문 단어 | 18% | lemon97, yuzu2451, pudding_tofu |
  | 아이디형 | 14% | parksun, choisun8734, kangbear9773 |
  | 팬닉 | 10% | 하루끝붙박이, 이틀끝 |

  현재 분포: 한글 포함 48%, 숫자 포함 54%, 평균 6.6자. 숫자 꼬리는 두 자리·출생연도(97, 03)·네 자리·한 자리로 갈립니다.

  AI와 사람이 **같은 풀**을 씁니다. AI임은 아이콘 라벨 하나로만 표시합니다 — 이름까지 기계스러우면
  아이콘만 바꾸는 설계가 깨집니다. 같은 `seed`에서 두 조건의 닉네임·본문이 글자 단위로 동일한 것을 확인했습니다.

  논문 기술: "닉네임은 실제 한국어 스트리밍 채팅의 표면 특성 분포에 맞춰 생성했으며,
  실제 이용자 핸들은 사용하지 않았다.
- **다른 방송 카드** — `FILLERS` 배열.

## 6. 알려진 한계

- `src=live`는 서버가 없어 모의 동작입니다. 실제 생성은 프록시가 붙어야 합니다.
- 영상이 플레이스홀더입니다. 실제 클립으로 바꾸면 `SPAN`(180초)과 `POLL_AT`(20초)도 맞춰야 합니다.
- 시청 화면에서 AI 비율 표시를 뺐습니다. 조작 인지는 안내 페이지와 채팅 줄별 AI 아이콘·사용자 카드가 받칩니다. 조작 점검 문항에서 확인이 필요합니다.
- 제한 시간을 거는 모드에서는 투표를 일찍 끝낸 참가자가 해제까지 기다립니다. 잠긴 채팅창에 남은 시간을 띄워 두었지만, 이 구간의 이탈을 파일럿에서 확인해야 합니다.
- 실험자 패널을 제거했습니다. 조건을 눈으로 바꿔보려면 개별 파라미터를 쓰세요.
